## 项目一句话定位

  

`AI Relationship Oracle` 是一个围绕情感关系场景运行的 AI 顾问系统。用户提供自己和对象的基础出生信息后即可直接提问，系统会自动建立对象与关系记忆，并结合八字、心理学、塔罗、RAG 和长期记忆，输出结构化关系洞察与行动建议。

## 当前统一后的核心架构

  

### 1. 线上系统

  

```text

用户

  ↓

FastAPI

  ↓

LangGraph

  ↓

GPT / Claude

  ↓

返回结果

```

  

### 2. 离线评测系统

  

```text

Evaluation Harness

  ↓

测试 Case

  ↓

Agent Workflow

  ↓

GPT / Claude

  ↓

评分器（规则 + LLM Judge + Ragas）

  ↓

评测报告

```

  

### 3. 数据结构分层

  

```text

Profile（事实档案）

+

Memory（AI 关系记忆）

```

  

- `Profile`：用户填写、系统计算，不允许模型随意改写

- `Memory`：系统在聊天与分析中持续沉淀的关系语义层

## V1 核心闭环

  

V1 现在不再定义为“用户手工维护完整关系状态和时间线”，而是优先跑通以下闭环：

  

```text

用户注册 / 登录

  ↓

填写自己的基础出生信息

  ↓

可选填写对象基础信息，也可直接进入首次咨询

  ↓

用户发起咨询

  ↓

系统自动提取对象、自动建档、自动生成初始关系快照

  ↓

系统读取档案、关系记忆、工具结果与知识依据

  ↓

生成结构化关系洞察与建议

  ↓

保存聊天，并在重大事件触发时更新记忆

  ↓

用户主动触发时生成正式报告

```

## 当前已确定的关键产品决策

  

1. `relationship_profile`：AI 自动更新为主，用户可人工修正。

2. `relationship_event`：高置信度自动落库，低置信度进入候选区等待确认。

3. `memory_summary`：按 `user_id + partner_id` 维护唯一主摘要。

4. 首次咨询：允许无 `partner_id` 直接发问，系统自动抽取对象并生成初始档案。

5. 工具调用：由用户勾选分析维度动态决定是否调用八字、心理学、塔罗等工具。

6. `report`：不随每次聊天自动生成，仅在用户主动点击“生成报告”时落库。

7. 评测体系：V1 同时建设 `Harness + Ragas`，其中 Harness 做总控，Ragas 做 RAG 专项评测。

  

---

  

## V1 核心原则

  

1. 情感关系优先，不做泛命理平台。

2. 关系事实优先于玄学推断。

3. 八字、塔罗、心理学是辅助分析维度，不是唯一裁决者。

4. 不输出绝对化结论，例如“她一定会回来”。

5. 输出核心是：洞察、风险、机会、行动建议。

6. 聊天和报告分离，报告必须由用户主动触发。

7. 记忆更新以重大事件驱动，避免每轮聊天都写入关系快照。

8. 所有关键架构变更都必须经过离线评测系统验证。

## 重要术语约定

  

- `Intent Router（意图路由器）`：判断用户问题类型，并决定进入哪条流程。

- `Entity Extractor（实体提取器）`：从用户首轮输入中提取对象，例如 Sarah，并支持自动建档。

- `Profile Loader（档案加载器）`：读取 `user_profile` 与 `partner_profile`。

- `Memory Builder（记忆构建器）`：整合关系快照、关系事件、长期摘要与短期上下文。

- `Event Detector（事件检测器）`：从聊天中识别重大关系变化，并触发事件写入与关系快照更新。

- `Compatibility Engine（融合分析引擎）`：融合八字、塔罗、心理学和关系事实，输出统一结构化结果。

- `Prompt Center（提示词中心）`：集中管理 Prompt 模板和输出规则。

- `Knowledge RAG（知识检索增强生成）`：为解释层提供理论依据与引用参考。

- `Evaluation Harness（AI 评测框架）`：用于整链路回归测试与版本对比。

- `Ragas`：接入 Harness 的 RAG 专项评测模块。
