
## 1. 路线图目标

  

本路线图用于指导 `AI Relationship Oracle` 从架构定稿进入实现。

  

当前路线图必须服务于已经确认的最终版架构：

  

1. 首次咨询允许自动建档；

2. `Profile + Memory` 双层数据结构；

3. `relationship_profile` 重大事件驱动更新；

4. `memory_summary` 按 Partner 维度维护；

5. 报告与聊天分离；

6. V1 同时建设 `Harness + Ragas`。

  

---

  

## 2. V1 总目标

  

V1 的目标不是做一个“表单型关系管理工具”，而是完成一条稳定的顾问闭环：

  

```text

用户注册 / 登录

  ↓

填写自己的基础出生信息

  ↓

可选补对象资料，或直接进入咨询

  ↓

系统自动识别对象并建立初始关系记忆

  ↓

系统读取档案、记忆、工具结果与知识依据

  ↓

生成结构化关系建议

  ↓

保存聊天，并在重大事件时更新关系记忆

  ↓

用户主动生成正式报告

```

  

---

  

## 3. 开发阶段总览

  

```text

Phase 0：文档与实现边界锁定

Phase 1：事实档案层

Phase 2：首次咨询自动建档 + 基础聊天闭环

Phase 3：AI 关系记忆层

Phase 4：分析维度选择器 + 工具层

Phase 5：Compatibility Engine + Prompt Center

Phase 6：报告系统

Phase 7：RAG 知识库

Phase 8：Evaluation Harness + Ragas

Phase 9：部署与上线准备

```

  

---

  

## 4. Phase 0：文档与边界锁定

  

### 目标

  

在编码前确保团队对最终口径完全一致。

  

### 验收标准

  

- 首次咨询自动建档机制明确；

- 关系记忆更新规则明确；

- 报告触发规则明确；

- 评测体系边界明确；

- 不再保留“用户每次手工维护完整关系状态”的旧口径。

  

---

  

## 5. Phase 1：事实档案层

  

### 目标

  

完成 `Profile` 层。

  

### 后端任务

  

- 初始化 FastAPI

- PostgreSQL / SQLAlchemy / Alembic

- 创建：

  - `user`

  - `user_profile`

  - `partner_profile`

- 本人档案接口

- 对象档案接口

- 基础命盘计算

  

### 前端任务

  

- 注册 / 登录页

- 我的档案页

- 对象列表页

- 对象编辑页

  

### 验收标准

  

用户可以：

  

- 注册登录；

- 创建自己的基础档案；

- 手动新增对象；

- 编辑对象基础信息。

  

---

  

## 6. Phase 2：首次咨询自动建档 + 基础聊天闭环

  

### 目标

  

支持无 `partner_id` 的首次咨询。

  

### 后端任务

  

- `conversation`

- `conversation_message`

- `consultations`

- `Intent Router`

- `Entity Extractor`

- 自动创建：

  - `partner_profile`

  - 初始 `relationship_profile`

  - 初始 `memory_summary`

- LLM Provider

  

### 前端任务

  

- AI 咨询页

- 输入框 / 聊天 UI

- 未选对象也可直接发问

- 自动建档回填展示

  

### 验收标准

  

用户输入：

  

```text

我和 Sarah 分手三个月了，最近她点赞我朋友圈，她会回来吗？

```

  

系统可以：

  

- 自动识别 Sarah；

- 自动建对象；

- 自动建立初始关系记忆；

- 返回分析结果；

- 保存聊天。

  

---

  

## 7. Phase 3：AI 关系记忆层

  

### 目标

  

完成 `Memory` 层。

  

### 后端任务

  

- `relationship_profile`

- `relationship_event`

- `relationship_event_candidate`

- `memory_summary`

- Redis 短期上下文

- `Event Detector`

- `Memory Builder`

  

### 前端任务

  

- 关系记忆详情页

- 候选事件确认交互

- 关系快照纠偏交互

  

### 验收标准

  

- `relationship_profile` 只在重大事件触发时更新；

- 高置信度事件直接写入；

- 低置信度事件进入候选区；

- `memory_summary` 按 `user_id + partner_id` 维护；

- 用户可以修正关系快照。

  

---

  

## 8. Phase 4：分析维度选择器 + 工具层

  

### 目标

  

让用户决定本轮咨询启用哪些分析维度。

  

### 前端任务

  

实现：

  

```text

☑ 八字分析

☑ 心理学分析

☐ 塔罗分析

```

  

### 后端任务

  

- `analysis_methods` 支持

- `Tool Router`

- `Bazi Engine`

- `Psychology Engine`

- `Tarot Engine`

- 统一结构化结果格式

  

### 验收标准

  

- 工具链可动态启停；

- 工具输出统一 JSON；

- 不直接向用户输出工具原始长文。

  

---

  

## 9. Phase 5：Compatibility Engine + Prompt Center

  

### 目标

  

让多工具结果稳定融合，形成统一回答输入。

  

### 任务

  

- `Compatibility Engine`

- `Prompt Center`

- 规则骨架 + LLM 辅助融合

- 最终回答结构规范

  

### 验收标准

  

- 回答中稳定出现：

  - 关系判断

  - 风险

  - 机会

  - 行动建议

- 不出现绝对化断言；

- 资料缺失时有边界说明。

  

---

  

## 10. Phase 6：报告系统

  

### 目标

  

正式拆分聊天与报告。

  

### 任务

  

- `report`

- `POST /reports`

- `Report Builder`

- 报告列表页

- 报告详情页

  

### 验收标准

  

- 聊天不会自动生成报告；

- 用户点击后才生成正式报告；

- 报告可按对象查看。

  

---

  

## 11. Phase 7：RAG 知识库

  

### 目标

  

给工具结果和最终回答提供理论依据层。

  

### 任务

  

- `knowledge_document`

- Milvus 向量库

- 检索流程

- 引用压缩

- 与 Agent Workflow 对接

  

### 验收标准

  

- 检索结果相关；

- 不把 RAG 当用户记忆库；

- 回答 grounding 更稳。

  

---

  

## 12. Phase 8：Evaluation Harness + Ragas

  

### 目标

  

建立离线回归测试体系。

  

### 任务

  

- `evaluation_case`

- `evaluation_run`

- `evaluation_result`

- Harness Runner

- 规则评分

- LLM Judge

- Ragas 接入 `rag_evaluator`

  

### 验收标准

  

- 能比较 Prompt / Router / Memory / RAG / Compatibility 版本；

- 能识别绝对化断言；

- 能跑整链路回归集；

- 能跑 RAG grounding 专项集。

  

---

  

## 13. Phase 9：部署与上线准备

  

### 目标

  

确保 V1 进入可试运行状态。

  

### 必查内容

  

- 首次咨询自动建档可用；

- 关系记忆不串线；

- 重大事件更新规则正常；

- 报告触发逻辑正常；

- Harness 核心回归集通过；

- Ragas 核心 RAG 集通过。

  

---

  

## 14. 路线图结论

  

当前最合理的实现顺序是：

  

```text

先做事实档案

→ 再跑首次咨询自动建档

→ 再做 AI 关系记忆

→ 再做工具层与分析维度选择

→ 再做融合与 Prompt

→ 再拆报告系统

→ 再补 RAG 与评测

→ 最后上线

```

  

这条路线最符合当前已经定下来的最终版项目结构。
