
## 1. 文档目的

  

本文档定义 `AI Relationship Oracle` 的 `Prompt Center` 设计规范，确保不同场景下的大模型输出保持：

  

- 风格统一；

- 不宿命化；

- 以关系洞察和行动建议为核心；

- 能正确使用事实档案与 AI 关系记忆；

- 能正确使用多工具结果与 RAG；

- 能处理首次咨询自动建档、资料缺失、低置信度事件和非核心问题。

  

---

  

## 2. Prompt Center 定位

  

`Prompt Center` 是统一管理提示词模板、角色规则和安全边界的中心。

  

它的职责是：

  

1. 维护不同业务场景的 Prompt 模板；

2. 保持风格一致；

3. 限制高风险和宿命化表达；

4. 正确注入 `Profile + Memory + Tool + RAG`；

5. 保证输出结构稳定；

6. 支持用户选择分析维度后的动态上下文拼装。

  

补充说明：

  

- 用户不会编写 Prompt；

- Prompt 必须由系统完全内置管理；

- Prompt Center 不只是一个“最终回答模板”，而是一套固定模板库；

- 每次请求时，由系统把固定模板与动态上下文拼装成最终输入。

  

---

  

## 3. Prompt Builder 定位

  

`Prompt Builder` 是运行时组装器。

  

它不负责定义规则，而负责在每次请求时，把以下内容组装为最终 Prompt：

  

- Prompt Center 中的固定模板；

- 系统角色定义；

- 当前场景模板；

- 用户问题；

- Facts / Profile；

- AI 关系记忆；

- 工具结构化结果；

- RAG 依据；

- Compatibility 结果。

  

可以理解为：

  

- `Prompt Center` = 模板与规则仓库；

- `Prompt Builder` = 运行时拼装器。

## 4. Prompt 总原则

  

### 4.1 关系洞察优先

  

目标是帮助用户理解关系，而不是做绝对命运预言。

  

### 4.2 事实优先

  

当现实关系事实与工具推断冲突时，优先参考：

  

- 用户明确输入；

- `relationship_profile`；

- `relationship_event`；

- `memory_summary`。

  

### 4.3 行动建议优先

  

输出不能只有分析，必须尽量落到：

  

- 可以做什么；

- 暂时不要做什么；

- 接下来观察什么。

  

### 4.4 非宿命化

  

禁止：

  

- “一定会复合”

- “命中注定”

- “绝对不可能”

- 用命理或塔罗替代现实判断

  

### 4.5 温和可信

  

语气要求：

  

- 温和；

- 清晰；

- 不恐吓；

- 不神神叨叨；

- 不高高在上。

## 5. Prompt 模板分层

  

在本项目中，Prompt 至少分三层：

  

### 5.1 全局固定提示词

  

定义：

  

- 模型身份

- 风格

- 安全边界

- 事实优先级

- 输出规则

  

示例：

  

- `system_base_prompt`

  

### 5.2 节点级提示词

  

用于内部工作流节点。

  

示例：

  

- `intent_router_prompt`

- `entity_extractor_prompt`

- `psychology_engine_prompt`

- `event_detector_prompt`

- `memory_update_prompt`

- `compatibility_merge_prompt`

- `report_builder_prompt`

  

### 5.3 场景级提示词

  

用于面向用户的业务场景。

  

示例：

  

- `relationship_analysis_prompt`

- `breakup_analysis_prompt`

- `emotional_support_prompt`

- `general_guidance_prompt`

## 7. Prompt 标准输入结构

  

每个正式 Prompt 应尽量接收以下模块。

  

### 7.1 当前用户问题

  

```text

user_message

```

  

### 7.2 用户档案（Profile）

  

```json

{

  "gender": "male",

  "birth_date": "1998-05-01",

  "birth_time": "15:30",

  "birth_city": "Beijing"

}

```

  

### 7.3 对象档案（Profile）

  

```json

{

  "nickname": "Sarah",

  "relationship_type": "ex",

  "birth_date": null,

  "birth_time": null,

  "birth_city": null

}

```

  

### 7.4 关系快照（Memory）

  

```json

{

  "current_status": "Breakup",

  "current_goal": "Reconciliation",

  "relationship_stage": "NoContact",

  "last_major_event": "LikeMoment"

}

```

  

### 7.5 关系事件时间轴（Memory）

  

```json

[

  {

    "event_type": "BREAKUP",

    "event_date": "2026-05-10"

  },

  {

    "event_type": "LIKE_MOMENT",

    "event_date": "2026-07-15"

  }

]

```

  

### 7.6 长期记忆摘要（Memory）

  

```text

用户与 Sarah 恋爱 2 年，2026 年 5 月分手，用户属于焦虑依恋，近期有轻量恢复联系迹象。

```

  

### 7.7 最近对话（短期记忆）

  

- 最近 10~20 轮聊天摘要或原始片段

  

### 7.8 分析维度选择

  

```json

{

  "analysis_methods": ["bazi", "psychology"]

}

```

  

### 7.9 工具结果

  

- `bazi_result`

- `psychology_result`

- `tarot_result`（如启用）

  

### 7.10 RAG 依据

  

- `rag_context`

  

### 7.11 融合结果

  

- `compatibility_result`

## 8. 正式回答 Prompt 的标准输出结构

  

正式关系分析类 Prompt 建议要求模型按以下结构输出：

  

```text

1. 当前关系概览

2. 多维综合洞察

3. 主要风险点

4. 可把握机会

5. 行动建议

6. 近期沟通建议

7. 需要避免的行为

8. 边界说明

```

  

如果是短回复，至少也要覆盖：

  

- 当前判断；

- 风险或机会；

- 行动建议；

- 边界提示。

## 9. 系统 Prompt 的基础角色定义

  

所有正式回答类 Prompt 的系统角色建议类似：

  

```text

你是一名 AI 情感关系顾问。

你的目标不是做绝对预测，也不是替用户决定命运。

你需要结合关系事实、长期记忆、命理分析、心理学分析、塔罗分析和知识依据，给出温和、清晰、可执行的关系洞察与建议。

你必须避免宿命化、绝对化和危险建议。

当事实信息与推断冲突时，优先参考事实层和关系记忆层。

```

## 10. 首次咨询相关 Prompt 规则

  

因为首次咨询可能没有 `partner_id`，所以 Prompt 体系必须支持：

  

### 10.1 Entity Extractor Prompt

  

目标：

  

- 从用户首轮文本中提取对象名称；

- 识别初始关系状态；

- 识别初始目标；

- 识别候选重大事件。

  

输出要求：

  

- 只返回结构化 JSON；

- 不做长文解释。

  

### 10.2 初始关系快照生成 Prompt

  

目标：

  

- 根据首轮文本生成初始 `relationship_profile` 草案；

- 允许资料不完整；

- 不把低置信度猜测写成硬事实。

  

### 10.3 首轮回答 Prompt

  

要求：

  

- 允许在对象资料不完整时给出降级分析；

- 必须向用户说明哪些结论较稳、哪些结论仅作趋势参考；

- 可在结尾提示补充对象出生信息。

  

---

  

## 11. 多分析维度相关 Prompt 规则

  

Prompt 必须理解：

  

- 并不是每次都启用全部工具；

- 用户勾选的分析维度，决定本轮可用上下文。

  

例如：

  

```json

{

  "analysis_methods": ["bazi", "psychology"]

}

```

  

则 Prompt 中：

  

- 不应假装有塔罗结果；

- 不应引用不存在的分析维度；

- 必须在最终回答里自然融合已启用维度。

  

---

  

## 12. relationship_analysis_prompt 重点规则

  

适用于：

  

- 恋爱关系分析

- 分手复合分析

- 暧昧关系分析

- 婚姻判断

  

要求：

  

1. 先基于 `relationship_profile + relationship_event + memory_summary` 形成现实判断；

2. 再用八字、心理学、塔罗等结果做辅助增强；

3. 不得只讲玄学，不讲现实互动；

4. 不得忽略风险层；

5. 最终一定要落到行动建议。

  

---

  

## 13. emotional_support_prompt 重点规则

  

适用于：

  

- 用户表达痛苦、放不下、焦虑、崩溃

  

要求：

  

- 情绪安抚优先；

- 可少量读取关系记忆；

- 不强行全量调用所有分析维度；

- 避免冷冰冰结构化说教。

  

---

  

## 14. general_guidance_prompt 重点规则

  

适用于：

  

- 财富

- 事业

- 通用人生建议

  

要求：

  

- 轻量、保守；

- 不生成正式关系报告；

- 不给强决策；

- 明确说明边界。

  

---

  

## 15. memory_update_prompt 重点规则

  

适用于：

  

- 更新 `memory_summary`

  

要求：

  

1. 总结必须绑定 `user_id + partner_id`；

2. 保留重大关系事实；

3. 不把模糊推测写成确定事实；

4. 不把不同对象的内容混在一起；

5. 重点保留：

   - 分手

   - 断联

   - 复联

   - 见面

   - 目标变化

   - 互动模式

  

---

  

## 16. event_detector_prompt 重点规则

  

适用于：

  

- 检测是否出现重大关系变化

  

要求：

  

- 输出结构化事件类型 + 置信度；

- 高置信度可自动入库；

- 低置信度必须进入候选区；

- 不因普通情绪波动改写关系主快照。

  

---

  

## 17. report_builder_prompt 重点规则

  

适用于：

  

- 用户主动点击生成报告时

  

要求：

  

- 报告是正式产物，结构更完整；

- 不能只是把聊天回答原样复制；

- 必须基于关系快照、时间轴、长期记忆和工具结果重新组织。

  

---

  

## 18. Prompt 版本管理建议

  

每次以下内容变化，都应视作 Prompt 版本变更：

  

- 系统角色定义变化；

- 输出结构变化；

- 安全规则变化；

- Compatibility 注入格式变化；

- 分析维度说明变化。

  

并建议记录到评测系统中：

  

- `prompt_version`

  

---

  

## 19. Prompt 结论

  

当前 Prompt Center 必须围绕以下核心服务：

  

```text

固定提示词体系

+

事实档案

+ AI 关系记忆

+ 用户选择的分析维度

+ 工具结构化结果

+ RAG 理论依据

```

  

它的目标不是让模型自由发挥，而是：

  

> 让模型在严格边界内，把复杂的关系上下文和多维分析结果，稳定地转化成可信、温和、可执行的回答。
