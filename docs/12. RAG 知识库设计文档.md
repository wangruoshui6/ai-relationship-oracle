## 1. 文档目的

  

本文档定义 `AI Relationship Oracle` 的 `Knowledge RAG` 设计方案。

  

本文档回答以下问题：

  

1. 为什么项目需要 RAG；

2. RAG 在项目中的角色是什么；

3. 知识库应该收录什么；

4. 如何切片、向量化和检索；

5. 如何把检索结果注入 AI 咨询链路；

6. 如何与 Harness + Ragas 对接做专项评测。

  

---

  

## 2. RAG 基本定义

  

`RAG` 是 `Retrieval-Augmented Generation` 的缩写。

  

在本项目中，RAG 的定位不是“主分析器”，而是：

  

> 一个给工具层和最终回答层提供理论依据与 grounding 的辅助系统。

  

---

  

## 3. RAG 的角色边界

  

### 3.1 RAG 是什么

  

- 理论依据库

- 检索式知识支持系统

- 回答 grounding 增强层

- 对工具结果的解释增强层

  

### 3.2 RAG 不是什么

  

- 不是用户记忆库

- 不是聊天记录库

- 不是业务数据库

- 不是替代八字 / 心理 / 塔罗的主分析引擎

- 不是 `memory_summary` 的替代品

  

### 3.3 三层分工

  

```text

规则 / 工具引擎负责：算与判

RAG 负责：找依据

LLM 负责：解释与表达

```

  

---

  

## 4. 为什么需要 RAG

  

即使系统已经有：

  

- 八字分析引擎

- 心理学分析引擎

- 塔罗分析引擎

- Compatibility Engine

- Prompt Center

  

仍然需要 RAG，因为它可以：

  

1. 提供理论依据；

2. 降低幻觉；

3. 稳定解释风格；

4. 提高 grounding；

5. 让回答更像“有依据的分析”，而不是“模型即兴生成”。

  

---

  

## 5. RAG 触发原则

  

RAG 不是每轮都必须触发。

  

### 建议触发场景

  

- 关系分析问题；

- 工具结果需要理论解释；

- 正式报告生成；

- 复杂情境下需要增强依据稳定性。

  

### 不建议强制触发场景

  

- 简单问候；

- 单纯情绪安抚；

- 非核心闲聊。

  

---

  

## 6. RAG 在工作流中的位置

  

推荐流程：

  

```text

用户问题

↓

Intent Router

↓

Profile / Memory 加载

↓

工具层输出结构化结果

↓

根据问题与工具结果抽取检索意图

↓

RAG 检索

↓

Compatibility Engine

↓

Prompt Builder

↓

LLM

```

  

说明：

  

- RAG 通常在工具层之后触发；

- 它不是“先检索再决定怎么分析”的主入口；

- 它更适合作为解释增强层。

## 7. 知识库内容范围

  

V1 建议知识库按三大类组织。

  

### 7.1 命理类知识库

  

推荐来源：

  

- 《滴天髓》

- 《渊海子平》

- 《三命通会》

- 《穷通宝典》

- 适合现代解释的八字资料

  

适合入库的内容：

  

- 五行解释

- 日主特征

- 十神基础含义

- 情感与关系维度相关解释

- 合盘中的关系模式

  

不建议入库的内容：

  

- 过于绝对和宿命化的断语

- 难以现代化解释的大段原文

- 无法验证来源的网络内容

  

### 7.2 塔罗类知识库

  

推荐来源：

  

- 牌义教材

- 牌阵说明文档

- 正逆位解释资料

- 关系问题场景下的牌义资料

  

适合入库的内容：

  

- 单张牌含义

- 关系场景中的常见解释

- 牌阵位置含义

- 正逆位差异

  

### 7.3 心理学类知识库

  

推荐来源：

  

- 依恋理论资料

- 亲密关系沟通资料

- 情绪调节资料

- 冲突模式与边界理论资料

  

适合入库的内容：

  

- 焦虑 / 回避 / 安全型依恋定义

- 追逃循环解释

- 沟通升级模式

- 修复关系的现实建议框架

## 8. 切片与元数据设计

  

### 8.1 切片原则

  

- 每个 chunk 保持主题单一；

- 不宜过长；

- 保留来源与类别标签；

- 古文资料尽量现代化整理后再切片。

  

### 8.2 元数据建议

  

每个 chunk 应附带：

  

- `source`

- `title`

- `category`

- `sub_category`

- `tags`

- `language`

  

例如：

  

```json

{

  "source": "psychology_attachment_notes",

  "category": "psychology",

  "sub_category": "attachment",

  "tags": ["anxious", "avoidant", "pursue-withdraw"]

}

```

## 9. 检索策略

  

### 9.1 检索输入来源

  

RAG 检索意图可来自：

  

- 用户当前问题；

- 工具结果中的核心标签；

- Compatibility Engine 需要补充依据的点。

  

例如：

  

- `复合`

- `断联后恢复联系`

- `焦虑依恋`

- `节制牌`

- `夫妻宫`

  

### 9.2 检索流程建议

  

```text

Query Builder

↓

Embedding

↓

Milvus Top-K 检索

↓

可选 rerank

↓

引用压缩

↓

输出 rag_context

```

  

### 9.3 输出结构建议

  

RAG 不只返回原始段落，而应返回结构化“检索包”：

  

```json

{

  "tool": "rag",

  "query_intents": ["anxious avoidant dynamic"],

  "references": [

    {

      "source": "psychology_attachment_notes",

      "snippet": "焦虑-回避组合常见于一方追近、一方退缩的互动模式。",

      "score": 0.88,

      "category": "psychology"

    }

  ]

}

```

## 10. RAG 与工具层的关系

  

RAG 不替代工具层，而是围绕工具结果做解释增强。

  

### 10.1 命理结果解释

  

当 `Bazi Engine` 输出：

  

- 情感表达克制

- 节奏不一致

- 有缘分基础

  

RAG 可检索对应理论依据。

  

### 10.2 塔罗结果解释

  

当 `Tarot Engine` 输出：

  

- 节制牌

- 恋人牌

- 圣杯二

  

RAG 可检索对应关系场景牌义。

  

### 10.3 心理结果解释

  

当 `Psychology Engine` 输出：

  

- 焦虑依恋

- 回避依恋

- 追逃模式

  

RAG 可检索心理学依据。

  

---

  

## 11. RAG 与 Prompt Builder 的关系

  

Prompt Builder 不应把大段原文直接塞给模型，而应：

  

1. 提取最相关的少量依据；

2. 保留来源与类别；

3. 作为 grounding 参考注入；

4. 防止喧宾夺主。

  

注入目标：

  

- 增强解释可信度；

- 提示模型不要脱离依据自由发挥。

## 12. RAG 与评测体系

  

V1 已确定：

  

```text

Harness + Ragas

```

  

其中：

  

- `Harness` 负责整链路评测；

- `Ragas` 负责 RAG 专项评测。

  

### 12.1 RAG 评测重点

  

应重点评测：

  

- retrieval relevance

- context precision / recall

- answer grounding

- faithfulness

  

### 12.2 评测示例

  

查询：

  

```text

夫妻宫

```

  

验证：

  

- 是否召回命理相关内容；

- 是否误召回塔罗无关内容；

- 是否被最终回答合理利用。

  

---

  

## 13. 关键约束

  

1. RAG 不能当用户记忆库；

2. RAG 不能直接替代工具判断；

3. RAG 不能为每轮闲聊强制触发；

4. RAG 不能把不相关片段塞给模型；

5. RAG 结果必须通过 Harness / Ragas 做回归测试。

  

---

  

## 14. RAG 结论

  

当前项目中的 RAG 应被严格定义为：

  

> 一个围绕八字、心理学、塔罗等工具结果，为最终回答和正式报告提供理论依据与 grounding 的辅助系统。

  

它服务于：

  

- 更稳的解释；

- 更强的依据感；

- 更低的幻觉率；

- 更可评测的知识注入层。
