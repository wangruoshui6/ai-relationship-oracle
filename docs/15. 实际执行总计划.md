## 1. 文档目的

  

本文档把当前 `AI Relationship Oracle` 的规划文档压缩成一份真正可执行的总计划。

  

当前版本已经对齐最终架构：

  

- 线上系统：`用户 → FastAPI → LangGraph → GPT → 返回结果`

- 离线系统：`Harness → Cases → Workflow → Judge → Report`

- 数据分层：`Profile + Memory`

- 产品入口：允许首次咨询自动建档

- 报告机制：用户主动触发生成

## 3. 项目执行总原则

  

### 3.1 先跑主闭环，再做增强

  

当前主闭环应定义为：

  

```text

注册 / 登录

  ↓

填写自己的基础出生信息

  ↓

直接咨询或补充对象信息

  ↓

首次咨询自动建档

  ↓

返回结构化分析结果

  ↓

保存聊天并沉淀关系记忆

  ↓

用户主动生成正式报告

```

  

### 3.2 先做事实档案，再做 AI 记忆

  

因为 AI 咨询必须先知道：

  

- 用户是谁；

- 对象是谁；

- 命盘基础是什么。

  

然后才能逐步沉淀：

  

- 当前关系状态；

- 历史时间线；

- 长期关系摘要。

  

### 3.3 先让用户低门槛进入，再做重交互

  

不能要求新用户第一次进来就维护复杂关系表单。

  

正确策略：

  

```text

先提问 → 先得到价值 → 后续逐步补资料

```

  

### 3.4 所有模块都围绕“同一个对象的持续咨询”服务

  

如果某个模块不能增强：

  

```text

围绕某个 partner 的长期理解能力

```

  

就不应优先。

  

### 3.5 Prompt 必须系统内置，不依赖用户输入

  

用户输入的是问题，不是 Prompt。

  

系统内部必须预先建设：

  

- 全局系统提示词

- 节点级提示词

- 场景级提示词

  

并由 Prompt Builder 在运行时完成组装。

  

其中：

  

- `Prompt Center` = 模板与规则仓库；

- `Prompt Builder` = 运行时拼装器。

```text

第一步：确认 P0 闭环范围

第五步：打通基础 AI 咨询闭环

第九步：拆分聊天与正式报告生成

第十步：接入 Harness + Ragas

第十一步：完成上线前验证

```

## 5. 分阶段执行计划

  

## Phase A：启动与对齐

  

### 目标

  

让所有参与者对最终架构理解一致。

  

### 必做事项

  

1. 锁定当前文档作为正式基线；

2. 确认 `Profile + Memory` 双层模型；

3. 确认首次咨询允许自动建档；

4. 确认报告必须主动触发；

5. 确认 Harness + Ragas 进入 V1；

6. 确认 Prompt 使用固定模板体系。

  

### 产出

  

- 实施基线文档

- 模块负责人分工

- P0 验收口径

  

---

  

## Phase B：事实档案层

  

### 目标

  

先把用户和对象的基础事实档案做出来。

  

### 后端任务

  

- 初始化 FastAPI 项目

- 配置 PostgreSQL / SQLAlchemy / Alembic

- 建表：

  - `user`

  - `user_profile`

  - `partner_profile`

- 用户档案保存接口

- 对象档案 CRUD 接口

- 建档时基础命盘计算能力

  

### 前端任务

  

- 注册 / 登录页

- 我的档案页

- 对象列表页

- 对象编辑页

  

### 验收标准

  

用户可以：

  

1. 注册登录

2. 创建自己的基础档案

3. 手动创建对象

4. 编辑对象基础信息

  

---

  

## Phase C：首次咨询自动建档 + Prompt 基础模板

  

### 目标

  

让用户即使没有 `partner_id` 也能直接发起第一次咨询，并且系统有最小可用 Prompt 体系。

  

### 后端任务

  

- `conversation`

- `conversation_message`

- `consultations` 接口

- `Intent Router`

- `Entity Extractor`

- 自动创建：

  - `partner_profile`

  - 初始 `relationship_profile`

  - 初始 `memory_summary`

- LLM Provider 抽象层

  

### AI 任务

  

- `system_base_prompt`

- `intent_router_prompt`

- `entity_extractor_prompt`

- `relationship_analysis_prompt`

- Prompt Builder 最小拼装逻辑

  

### 前端任务

  

- AI 咨询页

- 输入框 / 聊天 UI

- 未选对象也可发问

- 自动建档后对象状态回填展示

  

### 验收标准

  

用户第一次提问：

  

```text

我和 Sarah 分手三个月了，最近她点赞我朋友圈，她会回来吗？

```

  

系统可以：

  

- 自动识别 Sarah

- 自动创建对象

- 自动生成初始关系记忆

- 返回分析结果

- 保存会话与消息

## 6. 各角色当前最重要任务

  

### 产品

  

- 锁定当前文档基线；

- 不再反复改产品主边界；

- 仅做实现型补充。

  

### 后端

  

- 优先完成 Profile 与 Consultation 主链路；

- 为 Prompt Builder 预留结构化上下文字段。

  

### AI / Agent

  

- 先写固定 Prompt 最小集；

- 再接 Event / Memory / Compatibility；

- Prompt 改动全部接入 Harness。

  

### 前端

  

- 优先保证首次咨询入口顺滑；

- 分析维度选择器先做最小可用版；

- 报告按钮与普通聊天操作明显区分。

  

### QA

  

- 先围绕首次自动建档主链路设计测试；

- 再覆盖关系记忆、Prompt 回归和报告触发。

## 7. 关键的 7 个实现定论

  

1. 用户不会写 Prompt，Prompt 必须系统内置；

2. 首次咨询允许无 `partner_id`；

3. `Profile + Memory` 双层结构不变；

4. `memory_summary` 绑定 `user_id + partner_id`；

5. `relationship_profile` 采用重大事件驱动更新；

6. 报告与聊天分离；

7. `Harness + Ragas` 属于 V1 必备能力。
