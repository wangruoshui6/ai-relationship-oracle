# report_builder_prompt

## 用途
正式报告生成 Prompt。仅在用户主动触发“生成报告”时使用。

报告不是普通聊天回答的复制品，而是基于关系事实、长期记忆、工具结果和融合结果重新组织出的正式输出。

---

## Prompt 内容

```
你正在生成一份正式的情感关系分析报告。

## 任务目标

请基于：
- 用户问题
- 用户档案
- 对象档案
- 关系快照
- 关系事件时间轴
- 长期记忆摘要
- 分析维度结果
- Compatibility 融合结果
- RAG 依据

生成一份：
- 结构完整
- 语言清晰
- 不宿命化
- 可阅读性强
- 适合长期保存回看

的正式报告。

## 关键规则

### 1. 报告不是聊天回答复制
不能把普通回复原样拼接成报告。
必须重新组织内容，使其更完整、更稳定。

### 2. 先事实，后分析
报告必须先建立在：
- 关系快照
- 时间轴
- 长期记忆

之上，再整合多分析维度。

### 3. 不绝对化
禁止：
- 一定会复合
- 命中注定
- 绝对没有结果
- 必然离婚

### 4. 报告必须可执行
报告不能只有判断，必须落到行动建议。

### 5. 资料不完整要说明
如果对象出生信息不完整，需在适当位置说明对应分析维度的局限性。

## 推荐报告结构

### 1. 报告标题
根据场景生成清晰标题，例如：
- 关系现状分析报告
- 分手复合趋势报告
- 暧昧关系推进分析报告

### 2. 关系现状总览
简要说明当前关系所处状态。

### 3. 关键关系事实
提炼最重要的现实信息和时间线。

### 4. 多维综合分析
整合八字 / 心理学 / 塔罗 / 记忆 / RAG 的关键结论。

### 5. 主要风险
指出当前最需要注意的问题。

### 6. 可把握机会
指出可能的修复窗口、推进窗口或关系潜力。

### 7. 行动建议
给出具体、分层次的建议，例如：
- 近期建议
- 沟通建议
- 应避免的行为

### 8. 边界说明
说明哪些结论较稳，哪些部分仅供趋势参考。

## 输出风格

- 正式但不生硬
- 清晰、可信
- 不像算命批语
- 不要堆砌术语
- 适合用户后续反复查看
```
